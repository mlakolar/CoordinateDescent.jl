HighDimensionalModels — Module
HighDimensionalModels

Lasso estimators computed by coordinate descent: lasso, sqrt_lasso, scaled_lasso, feasible_lasso!, LassoPath, the penalized generalized linear models glm_lasso and GLMLassoPath, the group lasso group_lasso and GroupLassoPath, the multi-response lasso multi_lasso and MultiLassoPath, the inference after selection of R's hdm (rlasso, post_lasso, double_selection), and the varying-coefficient models varying_coefficient and varying_coefficient_lasso, with the kernels of KernelSmoothing.jl. They run the coordinate descent, the penalty paths and the reweighting of ProximalSolvers.jl on the losses and penalties of ProximalBase.jl, as does coordinate_descent!, which minimizes f(x) + g(x) for a loss f (a CoordinateDifferentiableFunction or a loss that ProximalSolvers knows) and a penalty g that separates across coordinates, such as the weighted ℓ1 norm NormL1. Low-rank multivariate fits use reduced_rank, nuclear_regression, sparse_reduced_rank, and sparse_svd_regression, with LowRankPath and CVLowRankPath for tuning. The lasso solvers accept real data and penalties of any type and convert them to a common floating point type: the element type of X and y promoted to a float, or that of the iterate passed to scaled_lasso! and feasible_lasso!.

Penalties on ordered coefficients and graphs are fitted by fused_lasso, trend_filter and generalized_lasso, using exact proximal steps, proximal gradient or specialized ADMM rather than coordinate descent.

HighDimensionalModels.LassoPath — Type
LassoPath(X, y, λpath, options=CDOptions(); max_hat_s=Inf, standardize_x=true, intercept=false, screening=true,
          gram=:auto, weights=nothing, offset=nothing, alpha=1, penalty=nothing, lla=nothing, lower=-Inf,
          upper=Inf, rng=Random.default_rng(), kwargs...)
LassoPath(X, y, options=CDOptions(); nλ=100, λminratio, kwargs...)

Lasso solutions β0path[k] and βpath[k] of

minimize  ‖y - β₀ - Xβ‖² / (2n) + λpath[k] ∑ⱼ ωⱼ |βⱼ|

along a decreasing sequence λpath, each one warm started from the previous solution, by ProximalSolvers.solve_path. The intercept β₀ is not penalized, and it is zero unless intercept is true. The loadings are the standard deviations ωⱼ = sqrt(∑ᵢ (Xᵢⱼ - x̄ⱼ)² / n) of the columns when standardize_x is true (centered only with an intercept) and ωⱼ = 1 otherwise.

Without λpath, the path has nλ values spaced evenly on the log scale from λmax, the smallest value whose solution is zero, down to λminratio ⋅ λmax; λminratio defaults to 0.01 when X has more columns than rows and to 1e-4 otherwise. The first value is λmax times 1 + √eps, so that rounding cannot make the first solution nonzero.

With screening, each λ is solved first over the coordinates kept by the sequential strong rule of Tibshirani et al. (2012), and the optimality conditions of the others are checked afterwards; coordinates that violate them are added and the problem solved again. kkt_checks[k] is the number of checks at λpath[k]: one when the rule kept every coordinate it should have, zero without screening. When options.warm_start is false, each value is solved from zero along its own path of options.num_steps levels, without screening.

The path stops early, after the first solution with more than max_hat_s nonzero coefficients; the returned λpath then contains only the values that were solved for. The solutions are stored as SparseVectors, so a path takes memory proportional to the number of nonzero coefficients. iterations[k] and converged[k] are the passes of coordinate descent at λpath[k] and whether it met its stopping rule. See also refit_lasso_path.

The keyword arguments kwargs that are not listed are fields of CDOptions that replace those of options, and the random order of coordinate descent is drawn from rng. With gram, the path is solved on the Gram matrix of the columns, and with weights and offset the loss is the weighted one, as described for lasso; λmax and the loadings are weighted too. fit(LassoPath, X, y, ...) is the same as LassoPath(X, y, ...). The functions of StatsAPI apply to the path: coef, predict and nobs; nobs is the number of observations, also stored as nobs.

alpha and penalty give the elastic net and other penalties, as for lasso: LassoPath(X, y; alpha=0.5) is glmnet's elastic-net path at a fixed α, whose λmax is that of the lasso divided by α, and LassoPath(X, y; penalty=MCP(1, 3)) the path of ncvreg, on standardized columns with standardize_x. Along a path of a nonconvex penalty, each solution is the local one reached from the previous solution, starting from zero at λmax. Without standardize_x, the exact steps of MCP and SCAD need the condition on a described for lasso. lla computes the path by local linear approximation, as described there. With penalty = CappedL1(1, a) and intercept = true (and lla = nothing, which then means LLA(; stages = 100)) it is the path of glmtlp's "tlp" with tau = a, with standardize_x as glmtlp's standardize. With lla = LLA(; stages = 1000, start = :previous), standardize_x = false and intercept = true, the paths of MCP, SCAD and CappedL1 are those of ncpen with x.standardize = FALSE (ncpen's own standardization differs from standardize_x). Its λmax is that of the first stage, the lasso with the weights pⱼ′(0)/λ. penalty holds the penalty at level one, NormL1(1, ω) for the lasso with loadings ω; the solution at λpath[k] minimizes the loss plus that penalty at level λpath[k], applied to scales .* β when scales is not nothing (standardize_x with a penalty other than the ℓ1 norm). lower and upper bound the coefficients, as for lasso; penalty is then Constrained(g, IndBox(l, u)), and λmax is the smallest level whose solution is zero under the bounds.

HighDimensionalModels.LassoSolution — Type
LassoSolution

Result returned by lasso, sqrt_lasso, scaled_lasso and feasible_lasso!.

Fields

  • x::SparseIterate: the estimated coefficients
  • residuals::Vector: y - intercept - X * x
  • penalty: the penalty at which x was computed, a NormL1 for the ℓ1 estimators, or the penalty of lasso's alpha or penalty at the level λ; with lower or upper, that penalty on the box of the bounds, Constrained(g, IndBox(l, u))
  • σ: an estimate of the noise level (see the documentation of each solver), or nothing
  • iterations::Int: passes of coordinate descent over the coordinates, summed over all the lasso fits the solver made
  • converged::Bool: whether coordinate descent met its stopping rule within max_iter passes and, for scaled_lasso! and feasible_lasso!, the outer iteration met its stopping rule within its max_iter iterations
  • intercept: the unpenalized intercept, zero unless the solver was called with intercept = true
  • hasintercept::Bool: whether the solver fitted an intercept
  • weights: the observation weights of the fit, nothing for none
  • scales: nothing when penalty applies to x, or the scales s of the columns when it applies to s .* x, the coefficients of the standardized columns X[:, j] / s[j] (standardize_x with a penalty other than the ℓ1 norm)

The functions of StatsAPI apply to it: coef, predict, residuals, nobs, dof and deviance.

HighDimensionalModels.feasible_lasso! — Method
feasible_lasso!(x, X, y, λ0, options=IterLassoOptions(); intercept=false, rng=Random.default_rng(), kwargs...)

Heteroscedasticity-robust lasso of Belloni, Chen, Chernozhukov and Hansen (2012), which uses data-driven penalty loadings. It alternates between the lasso

β̂ = argmin  ‖y - β₀ - Xβ‖² / (2n) + λ0 ∑ⱼ Γⱼ |βⱼ|

and the update of the loadings Γⱼ = sqrt(∑ᵢ (Xᵢⱼ - x̄ⱼ)² rᵢ² / n) from the residuals r = y - β̂₀ - Xβ̂, until the relative change in Γ is below options.opt_tol (by ProximalSolvers.reweight!), or warns after options.max_iter iterations. With max_iter = 0 there is no update: x is left as the initial procedure leaves it, the loadings are those of its residuals, and converged is false, without a warning. The intercept β₀ is not penalized; it and the column means x̄ⱼ are zero unless intercept is true.

The initial residuals are chosen by options.init_procedure (see IterLassoOptions); with :InitStd they come from a lasso with penalty λ0 σinit ∑ⱼ sⱼ |βⱼ|, sⱼ = sqrt(∑ᵢ (Xᵢⱼ - x̄ⱼ)² / n). Coordinate descent starts from and overwrites x, and each lasso fit is warm started from the previous one. Returns a LassoSolution whose penalty.w holds the loadings of the last fit and whose σ is the sample standard deviation of the residuals. The keyword arguments kwargs are fields of IterLassoOptions that replace those of options, as in feasible_lasso!(x, X, y, λ0; max_iter=50), and the random order of coordinate descent is drawn from rng.

HighDimensionalModels.lasso — Method
lasso(X, y, λ, options=CDOptions(); intercept=false, standardize_x=false, gram=:auto, weights=nothing,
      offset=nothing, alpha=1, penalty=nothing, lla=nothing, lower=-Inf, upper=Inf, rng=Random.default_rng(),
      kwargs...)
lasso(X, y, λ, ω, options=CDOptions(); intercept=false, gram=:auto, weights=nothing, offset=nothing,
      lower=-Inf, upper=Inf, rng=Random.default_rng(), kwargs...)

Solve the lasso

minimize  ‖y - β₀ - Xβ‖² / (2n) + λ ∑ⱼ ωⱼ |βⱼ|

by coordinate descent. The intercept β₀ is not penalized, and it is zero unless intercept is true. In the first form the loadings are ωⱼ = 1, or with standardize_x the standard deviations sqrt(∑ᵢ (Xᵢⱼ - x̄ⱼ)² / n) of the columns, with x̄ⱼ the column mean when intercept is true and zero otherwise; the coefficients are on the scale of the data either way. Returns a LassoSolution whose σ is the sample standard deviation of the residuals.

The keyword arguments kwargs are fields of CDOptions that replace those of options, as in lasso(X, y, λ; max_iter=10_000, opt_tol=1e-8), and the random order of coordinate descent is drawn from rng.

X can be any matrix and y any vector. A Matrix, or a view of a range of its rows or of some of its columns, is read in place. A SparseMatrixCSC stays sparse; coordinate descent still reads its columns entry by entry, so for now it is slower than the dense matrix. Any other matrix, such as a transpose or a view of selected rows, is copied once into a Matrix (a SparseMatrixCSC if it is sparse). The same holds for every solver of this package.

With gram = true, coordinate descent works on the Gram matrix of the (centered) columns, A = X'X / n, instead of the residuals. Each coordinate step then costs O(p) instead of O(n), after O(np²) operations and p² numbers of memory to form A. The loss, the stopping rule and so the solution are the same, to the tolerance. Forming A pays off over the many passes of a path when n ≥ p, but rarely at one λ. The default, gram = :auto, uses it for LassoPath on a dense X with n ≥ p and p ≤ 2000, and never at one λ.

With observation weights w (nonnegative, with a positive sum) and an offset o, the loss is

∑ᵢ wᵢ (yᵢ - oᵢ - β₀ - Xᵢ'β)² / (2 ∑ᵢ wᵢ).

Dividing by ∑ᵢ wᵢ follows glmnet: λ means the same with and without weights, unit weights give the unweighted fit, integer weights the fit of replicated rows, and zero weights leave observations out. The intercept, the loadings of standardize_x (sqrt(∑ᵢ wᵢ (Xᵢⱼ - x̄ⱼ)² / ∑ᵢ wᵢ)) and the Gram matrix are weighted as well. The residuals are y - o - β₀ - Xβ, and with weights σ is their weighted root mean square, sqrt(∑ᵢ wᵢ rᵢ² / ∑ᵢ wᵢ).

Other penalties

alpha < 1 gives glmnet's elastic net, λ (α ∑ⱼ |βⱼ| + (1 - α) ‖β‖² / 2), for 0 < α ≤ 1. penalty gives another penalty of ProximalBase whose level λ replaces: NormL1(1, w) and NormL1Nonneg(1, w) (the lasso and the nonnegative lasso with weights w), ElasticNet(1, λ2, w) (λ ∑ⱼ wⱼ|βⱼ| + λ2 ‖β‖²/2, with λ2 fixed), Scaled(ElasticNet(α, 1 - α, w), 1) (the elastic net with weights on its ℓ1 part), and the nonconvex MCP(1, a), SCAD(1, a), CappedL1(1, a) (λ min(|βⱼ|, a), the capped ℓ1 penalty of T. Zhang, 2010, and the truncated ℓ1 penalty of Shen, Pan and Zhu, 2012) and LogPenalty(1, ε) (λ log(1 + |βⱼ|/ε)), whose parameters are kept. The level of the penalty given is not used: MCP(1, 3) means "MCP with a = 3".

alpha solves the objective of glmnet's documentation. glmnet's gaussian family scales y to unit standard deviation internally, which divides the ridge part by sd(y), the population standard deviation of y (weighted with weights). So glmnet's solutions are those of penalty = Scaled(ElasticNet(α, (1 - α) / sd(y)), 1), and they equal those of alpha when sd(y) = 1.

With standardize_x, the penalty applies to the coefficients of the standardized columns X[:, j] / sⱼ, sⱼ their standard deviations, as in glmnet and ncvreg; the coefficients returned are those of the columns of X. For the ℓ1 norm this is the same as the loadings ωⱼ = sⱼ, which is how it is computed. For the other penalties X is divided by s once (a copy), and s is stored as the solution's scales.

A nonconvex penalty has local solutions, and the one found depends on the algorithm and the starting point. As in ncvreg, MCP and SCAD are computed by exact coordinate steps along options.num_steps levels from λmax, the smallest level with a zero solution, down to λ, each solved to the tolerance and warm started from the previous one; num_steps = 0 solves at λ from zero. Use LassoPath for the solutions at many levels. With options.warm_start false, a convex penalty other than the ℓ1 norm is also solved along such a path.

The exact steps need each coordinate problem to be convex: a vⱼ > 1 for MCP and (a - 1) vⱼ > 1 for SCAD, where vⱼ is the curvature of the loss along column j, its mean square ∑ᵢ (Xᵢⱼ - x̄ⱼ)² / n (centered with an intercept, weighted with weights, and of the standardized column with standardize_x). The path throws an ArgumentError when a column fails it, since the step could then leave zero where the test of λmax and screening says that zero is optimal. With standardize_x, vⱼ = 1, so ncvreg's conditions a > 1 and a > 2 suffice; without it, a column of variance at most 1/a fails. Take standardize_x = true, a larger a, or lla.

lla computes a nonconvex penalty by local linear approximation (LLA, or reweighted ℓ1) instead: lla = LLA(; stages = 2, tol = 1e-12, start = :lasso) (ProximalSolvers' LLA, exported) solves a sequence of weighted lassos with the weights pⱼ′(|βⱼ|)/λ at the previous solution, each a convex problem, by the coordinate descent of options; the inner solver of the LLA given is not used. From zero the first stage is the lasso. The stages stop after stages, or once the weights change by at most tol, relative to the largest one.

  • LLA(), two stages, is the two-step estimator of Fan, Xue and Zou (2014); with MCP and SCAD it has no condition on a.
  • LLA(; stages = 100) iterates until the weights stop changing, as the multi-stage convex relaxation of T. Zhang (2010), the difference of convex functions of Shen, Pan and Zhu (2012, glmtlp's "tlp") and the reweighted ℓ1 of Candès, Wakin and Boyd (2008). CappedL1 and LogPenalty have no exact path and use it when lla is nothing.
  • With start = :lasso the stages at λ start from the lasso at λ, as in the papers; with start = :previous they start from the solution at the previous level of a path of options.num_steps levels from λmax, as ncpen does.

lla does not take bounds (lower, upper), and it applies to these four penalties only. With lla, converged says whether coordinate descent converged in every stage.

Bounds

lower and upper bound the coefficients, lower ≤ β ≤ upper, as glmnet's lower.limits and upper.limits do: each is a number or a vector with a bound per coefficient, and zero must be feasible, lower ≤ 0 ≤ upper. For example, lower = 0 gives the nonnegative lasso, and upper = 0 with lower = 0 for a coefficient keeps it at zero. The intercept is not bounded. The penalty becomes Constrained(g, IndBox(l, u)), which keeps coordinate descent separable, and λmax and screening use only the directions the bounds allow, so that λmax of the nonnegative lasso is maxⱼ (Xⱼ'y / n)₊ / ωⱼ. With standardize_x and a penalty other than the ℓ1 norm, which applies to s .* β, the bounds of the stored penalty are s .* lower and s .* upper. Bounds work with every penalty above, in lasso, LassoPath, adaptive_lasso (through its keywords), CVLassoPath and glm_lasso.

HighDimensionalModels.refit_lasso_path — Method
refit_lasso_path(path::LassoPath, X, y)

Least squares refits on the supports along a LassoPath. Returns a Dict that maps each distinct support S (a vector of column indices) to X[:, S] \ y, or, when the path has an intercept, to [1 X[:, S]] \ y, whose first entry is the intercept.

Consecutive supports along a path differ by a few columns, so the Cholesky factor of X[:, S]'X[:, S] is updated from one support to the next (ProximalSolvers' RefitCache) instead of computed again. A support with at least n columns, or one whose columns are nearly collinear, is refit by \, which gives the minimum-norm solution.

HighDimensionalModels.scaled_lasso! — Method
scaled_lasso!(x, X, y, λ, ω, options=IterLassoOptions(); intercept=false, weights=nothing, offset=nothing,
             rng=Random.default_rng(), kwargs...)
scaled_lasso(X, y, λ, ω, options=IterLassoOptions(); intercept=false, weights=nothing, offset=nothing,
            rng=Random.default_rng(), kwargs...)
scaled_lasso!(x, f::CDSqrtQuadraticLoss, λ, ω, options=CDOptions(); rng=Random.default_rng(), kwargs...)

Scaled lasso of Sun and Zhang (2012), which estimates the coefficients and the noise level jointly:

minimize  ‖y - β₀ - Xβ‖² / (2nσ) + σ/2 + λ ∑ⱼ ωⱼ |βⱼ|   over β and σ > 0.

The intercept β₀ is not penalized, and it is zero unless intercept is true. The minimum over σ is at σ̂ = ‖y - β₀ - Xβ‖ / √n, so β̂ solves the square-root lasso of Belloni, Chernozhukov and Wang (2011),

minimize  ‖y - β₀ - Xβ‖ / √n + λ ∑ⱼ ωⱼ |βⱼ|,

which one run of coordinate descent solves (on CDSqrtLassoLoss, with the penalty level √n λ), with the options options.options_cd; the other fields of IterLassoOptions are not used. Coordinate descent starts from and overwrites x (unless options.options_cd.warm_start is false). Returns a LassoSolution whose σ is σ̂, and whose penalty is that of the lasso that β̂ solves, NormL1(λσ̂, ω).

The third form solves the same problem from sufficient statistics: with the loss CDSqrtQuadraticLoss(A, b, c), A = X'X/n, b = -X'y/n and c = y'y/n, it needs neither X nor y, and a coordinate update costs O(p) instead of O(n). With A = S, b = -S[:, j], c = S[j, j] and ω[j] = Inf it is the scaled lasso of variable j on the others from their covariance matrix S, as in the precision matrix estimator of Sun and Zhang (2013); for all the variables, check S once and build the losses with check = false. Its solution has no residuals (an empty vector) and no intercept.

The keyword arguments kwargs are fields of the options that replace those of options (of IterLassoOptions in the first two forms, of CDOptions in the third), and the random order of coordinate descent is drawn from rng. With observation weights w and an offset o, the loss is ∑ᵢ wᵢ rᵢ² / (2σ ∑ᵢ wᵢ) + σ/2 for the residuals r = y - o - β₀ - Xβ, so that σ̂ = sqrt(∑ᵢ wᵢ rᵢ² / ∑ᵢ wᵢ).

Before version 0.6.1, scaled_lasso! alternated lasso fits with updates of σ̂ until the relative change of σ̂ was below options.opt_tol (by default 1e-2), which stopped short of the solution and solved a lasso at every iteration.

HighDimensionalModels.sqrt_lasso — Method
sqrt_lasso(X, y, λ, options=CDOptions(); intercept=false, standardize_x=true, gram=:auto, weights=nothing,
          offset=nothing, rng=Random.default_rng(), kwargs...)
sqrt_lasso(X, y, λ, ω, options=CDOptions(); intercept=false, gram=:auto, weights=nothing, offset=nothing,
          rng=Random.default_rng(), kwargs...)

Solve the square-root lasso of Belloni, Chernozhukov and Wang (2011)

minimize  ‖y - β₀ - Xβ‖ + λ ∑ⱼ ωⱼ |βⱼ|

by coordinate descent, with an unpenalized intercept β₀ that is zero unless intercept is true. In the first form the loadings are the standard deviations ωⱼ = sqrt(∑ᵢ (Xᵢⱼ - x̄ⱼ)² / n) of the columns when standardize_x is true (centered only with an intercept) and ωⱼ = 1 otherwise. The optimal λ does not depend on the noise level. Returns a LassoSolution whose σ is the sample standard deviation of the residuals. The keyword arguments kwargs, gram and rng are as for lasso; on the Gram matrix the loss is the square root of a quadratic (as in CDSqrtQuadraticLoss). With observation weights w and an offset o, the loss is the weighted norm sqrt(∑ᵢ wᵢ (yᵢ - oᵢ - β₀ - Xᵢ'β)²), the loadings are weighted as in lasso, and σ is the weighted root mean square of the residuals.

HighDimensionalModels.adaptive_lasso — Method
adaptive_lasso(X, y, λ, options=CDOptions(); init=:lasso, initλ=λ, γ=1, intercept=false, standardize_x=false,
              kwargs...)

The adaptive lasso of Zou (2006),

minimize  ‖y - β₀ - Xβ‖² / (2n) + λ ∑ⱼ |βⱼ| / |β̃ⱼ|^γ,

whose loadings come from a first estimate β̃: large coefficients are penalized less, so that they are less biased, and small ones more, so that fewer variables that do not matter are selected. β̃ is

  • init = :lasso: the lasso at initλ, by default λ, with intercept, standardize_x and the keywords kwargs;
  • init = :ridge: ridge regression at initλ, ‖y - β₀ - Xβ‖² / (2n) + initλ ‖β‖² / 2, on the standardized columns with standardize_x (glmnet's alpha = 0);
  • init = β̃, a vector: for example least squares, X \ y when n > p, or the coefficients of a lasso whose level was chosen by cross-validation.

A coefficient with β̃ⱼ = 0 has an infinite loading and stays at zero. The second fit has no standardization, as with γ = 1 the loadings already make it invariant to the scales of the columns. The keywords kwargs (weights, offset, gram, rng and the fields of CDOptions) apply to both fits. Returns the LassoSolution of the second fit, whose penalty is NormL1(λ, ω) with the loadings ωⱼ = 1/|β̃ⱼ|^γ.

Reference: H. Zou (2006). The adaptive lasso and its oracle properties. Journal of the American Statistical Association 101(476), 1418–1429.

HighDimensionalModels.GLMLassoPath — Type
GLMLassoPath(X, y, loss = ProximalBase.Logistic(), options = CDOptions(); nλ = 100, λminratio, kwargs...)
GLMLassoPath(X, y, λpath, loss = ProximalBase.Logistic(), options = CDOptions();
             intercept = true, standardize_x = true, weights = nothing, offset = nothing,
             alpha = 1, penalty = nothing, lower = -Inf, upper = Inf, screening = true, max_hat_s = Inf,
             devmax = 0.999, newton_tol = 1e-8, newton_max_iter = 100, rng = Random.default_rng())

Solutions β0path[k] and βpath[k] of the penalized generalized linear model of glm_lasso along a decreasing sequence λpath, each one warm started from the previous solution and its intercept, by proximal Newton with the inner coordinate descent of options (ProximalSolvers' solve_path with ProxNewton).

Without λpath, the path has nλ values spaced evenly on the log scale from λmax, the smallest value whose solution is zero (at the intercept of the fit with β = 0), down to λminratio ⋅ λmax; λminratio defaults to 0.01 when X has more columns than rows and to 1e-4 otherwise. The first value is λmax times 1 + √eps, so that rounding cannot make the first solution nonzero.

With screening, each λ is solved first over the coordinates kept by the sequential strong rule of Tibshirani et al. (2012), and the optimality conditions of the others are checked afterwards (kkt_checks[k] times at λpath[k]), as in LassoPath. The path stops early after the first solution with more than max_hat_s nonzero coefficients, or once the fit explains a fraction devmax of the null deviance, as glmnet's does: along a logistic path on separable data the coefficients grow without bound, and the explained fraction devratio[k] = 1 - deviance / nulldeviance tends to one. devmax = 1 turns this off. The returned λpath then contains only the values that were solved for. iterations[k] and converged[k] are the passes of coordinate descent at λpath[k], summed over the proximal Newton steps, and whether the solve met its stopping rules. nobs is the number of observations.

alpha, penalty, lower and upper are as for glm_lasso; along a path of a nonconvex penalty, each solution is the local one reached from the previous solution. penalty holds the penalty at level one (NormL1(1, ω) for the lasso), applied to scales .* β when scales is not nothing. coef, predict and nobs apply to the path, as for LassoPath, and fit(GLMLassoPath, X, y, ...) is GLMLassoPath(X, y, ...).

HighDimensionalModels.glm_lasso — Method
glm_lasso(X, y, λ, loss = ProximalBase.Logistic(), options = CDOptions();
         intercept = true, standardize_x = true, weights = nothing, offset = nothing,
         alpha = 1, penalty = nothing, lower = -Inf, upper = Inf, newton_tol = 1e-8, newton_max_iter = 100,
         rng = Random.default_rng())

Solve the penalized generalized linear model

minimize  ∑ᵢ wᵢ ℓ(β₀ + xᵢ'β + oᵢ, yᵢ) / ∑ᵢ wᵢ + λ ∑ⱼ ωⱼ |βⱼ|

for a scalar loss ℓ of ProximalBase: ProximalBase.Logistic(), the negative log-likelihood of logistic regression (yᵢ ∈ [0, 1], usually {0, 1}); ProximalBase.Poisson(), Poisson regression with the log link (yᵢ ≥ 0); ProximalBase.Huber(δ); or a loss of your own. The observation weights wᵢ (nonnegative, one when omitted) and the offset oᵢ (zero when omitted) are those of weights and offset. The intercept β₀ is not penalized, and it is zero unless intercept is true. With standardize_x the loadings ωⱼ are the standard deviations of the columns, weighted by w and centered at their weighted means with an intercept, so that the coefficients are on the scale of the data; otherwise ωⱼ = 1. These are glmnet's conventions and defaults. lower and upper bound the coefficients, lower ≤ β ≤ upper, as for lasso.

alpha and penalty give the elastic net and the other penalties, as for lasso: alpha < 1 is glmnet's elastic net λ (α ∑ⱼ |βⱼ| + (1 - α) ‖β‖² / 2), and penalty a penalty of ProximalBase whose level λ replaces (ElasticNet(1, λ2), MCP(1, a), SCAD(1, a), NormL1Nonneg(1), or NormL1(1, w) for weights). With standardize_x, such a penalty applies to the coefficients of the standardized columns, as in glmnet; the coefficients returned are those of the columns of X, and the scales are stored in the solution's scales. The elastic net equals glmnet's binomial and poisson fits. A nonconvex penalty (MCP, SCAD) is computed along options.num_steps levels from λmax whatever options.warm_start, as ncvreg does; num_steps = 0 solves at λ from zero. The solutions are stationary points of the objective above. ncvreg's binomial and poisson families do not solve it: their coordinate steps scale the concavity of the penalty by the weighted curvature of each column at the current fit (they divide by v (1 - 1/a) where the exact step divides by v - 1/a), so their solutions differ (in its gaussian family v = 1 and the two agree).

The problem is solved by proximal Newton (ProximalSolvers' ProxNewton, the method of glmnet): each step minimizes the weighted least-squares model of the loss at the current fit by coordinate descent with options, then backtracks, until the objective changes by less than newton_tol relative to its value or after newton_max_iter steps. With options.warm_start false (or a nonconvex penalty), the solution is computed along options.num_steps levels from λmax (see GLMLassoPath), each warm started from the previous one; otherwise it is computed directly, starting from β = 0 and the intercept of the fit with β = 0. The random order of coordinate descent is drawn from rng. Returns a GLMLassoSolution.

y = Float64.(rand(n) .< 1 ./ (1 .+ exp.(-X * β)))
sol = glm_lasso(X, y, 0.05)                               # logistic
sol = glm_lasso(X, counts, 0.05, ProximalBase.Poisson(); offset = log.(exposure))

Fit mean(rho_tau(y - intercept - X*β - offset)) + λ*sum(w .* abs.(β)) along a nonincreasing, finite, nonnegative grid. Every saved level retains both coefficients and raw dual scores, including at zero residuals. path[k] is a QuantileLassoSolution; path.λpath contains the returned levels and requested_λpath the requested grid. complete is false when a limit stops the path. There is no coefficient or dual interpolation: coef(path, λ) requires a saved level.

method=:exact uses HiGHS dual simplex with an analytic quantile starting basis and reuses that basis/model along the path. Load HiGHS to activate the optional extension. initial_basis=:default disables the analytic start; simplex=:primal selects primal simplex. time_limit limits the entire exact path between levels and passes the remaining time to HiGHS. Preparation and diagnostics can overrun that limit, and automatic-grid preparation precedes the path timer. A stopped path retains available primal–dual results and the termination status; it never fills missing levels.

method=:smooth uses the existing proximal Newton path with the Epanechnikov convolution loss at explicit bandwidth (default 0.2). Its raw dual scores are the smoothed loss scores, not exact check-loss duals. time_limit is currently supported only by the exact backend. options, newton_tol, newton_max_iter, screening and rng control proximal Newton.

The intercept is unpenalized (intercept=true). penalty_factors are finite nonnegative slope weights, one by default. With standardize_x=true (the default), they are multiplied by column population standard deviations, centered when fitting an intercept. Coefficients and duals remain on the original data scale. Zero factors and λ=0 are supported on explicit grids; the automatic grid requires positive effective factors. offset is fixed and unpenalized. Observation weights and formula fits are not implemented here. Inputs are converted to Float64; sparse designs remain sparse.

The automatic grid starts at the intercept-only score maximum, inflated for roundoff, and ends at λminratio times that maximum. This is a numerical path, not pivotal calibration or cross-validation; use quantile_lambda or CVQuantileLassoPath for those choices. tol=2e-5 is the external KKT and relative raw-gap tolerance. Backends supporting convolution certificates also use it during smoothed fitting, honoring a smaller positive options.gaptol. An explicit options.gaptol=0 keeps the legacy objective-change rule; older backends retain their original stopping and are checked afterward.

For positive λ and factors, the certificate projects scores onto their box and intercept constraint, then contracts to meet the slope constraints. With zero λ or any zero factor it uses the feasible zero vector, whose bound may be loose; numerical convergence still checks the raw pair. No inferential validity is asserted merely from solver convergence.

Simulate a fixed-quantile pivotal penalty in the normalization of quantile_lasso: mean check loss plus λ*sum(w .* abs.(β)). For independent uniforms Uᵢ, simulate max_j abs(sum_i Zᵢⱼ*(tau - (Uᵢ < tau)))/(n*wⱼ) and return c times its empirical (1-gamma) quantile (linear interpolation, R's type 7). All effective slope loadings must be positive; unpenalized slopes require a separately justified calibration or an explicit λ. The rule calibrates exact check-loss scores; it is not a bandwidth calibration or a finite-sample guarantee for a convolution-smoothed fit.

HighDimensionalModels.group_lasso — Method
group_lasso(X, y, λ, groups, options = CDOptions(); intercept = true, standardize = :orthonormal,
           groupweights = sqrt.(length.(groups)))

The group lasso

minimize  ‖y - β₀ - Xβ‖² / (2n) + λ ∑ₖ wₖ ‖X̃_Gₖ βGₖ‖₂ / √n

for disjoint groups Gₖ that cover the columns of X (give a column its own group to treat it alone, and a zero weight to leave a group unpenalized), with an unpenalized intercept β₀ that is zero unless intercept is true, and X̃_G the columns of G, centered with an intercept. The weights default to wₖ = √|Gₖ|.

With standardize = :orthonormal, the default, the penalty is on the fitted values of each group, as above, which makes the estimate invariant to a change of basis within a group (Simon and Tibshirani, 2012; R's grpreg). It is fitted on orthonormalized groups: each X̃_G is factored by a pivoted QR as Z_G R̃, with Z_G'Z_G / n = I, the group lasso is solved in the coefficients θ_G = R̃ β_G by block coordinate descent, whose steps are then exact, and mapped back. The columns of a group that are linear combinations of its other columns get zero coefficients. With standardize = :none, the penalty is λ ∑ₖ wₖ ‖βGₖ‖₂ on the columns as given.

Coordinate descent runs with options; with options.warm_start false the solution is computed along options.num_steps levels from λmax. Returns a GroupLassoSolution. See also GroupLassoPath.

HighDimensionalModels.sparse_group_lasso — Method
sparse_group_lasso(X, y, λ, groups, options = CDOptions(); alpha = 0.95, intercept = true, standardize_x = true,
                 groupweights = sqrt.(length.(groups)), rng = Random.default_rng())

The sparse group lasso of Simon, Friedman, Hastie and Tibshirani (2013),

minimize  ‖y - β₀ - Xβ‖² / (2n) + λ (α ∑ⱼ |β̃ⱼ| + (1 - α) ∑ₖ wₖ ‖β̃_Gₖ‖₂),

which selects groups, as the group lasso does, and also variables within the selected groups, for disjoint groups Gₖ that cover the columns of X. With standardize_x, β̃ = s .* β are the coefficients of the columns divided by their standard deviations s (centered with an intercept); otherwise β̃ = β. R's sparsegl and SGL scale the columns to unit Euclidean norm instead, √n times the standard deviation, so their level λ is √n λ here. The coefficients returned are those of the columns of X. alpha mixes the two terms: alpha = 1 is the lasso and alpha = 0 the group lasso on the columns as given (group_lasso(...; standardize = :none)); the default 0.95 is SGL's. The weights default to wₖ = √|Gₖ|, and a zero weight with alpha = 0 leaves a group unpenalized. The intercept β₀ is not penalized, and it is zero unless intercept is true.

It is solved by block coordinate descent on the groups (ProximalSolvers' CD on an AtomIterate, whose block steps are the exact proximal operator of the penalty plus a quadratic bound), with options; with options.warm_start false the solution is computed along options.num_steps levels from λmax. The random order is drawn from rng. Unlike group_lasso, the groups are not orthonormalized: the ℓ1 term is not invariant to a change of basis within a group. Returns a SparseGroupLassoSolution. See also SparseGroupLassoPath.

Reference: N. Simon, J. Friedman, T. Hastie and R. Tibshirani (2013). A sparse-group lasso. Journal of Computational and Graphical Statistics 22(2), 231–245.

HighDimensionalModels.CVLassoPath — Method
CVLassoPath(X, y, options = CDOptions(); nfolds = 10, folds = nothing, rng = Random.default_rng(),
            threads = true, nλ = 100, λminratio, intercept = false, standardize_x = true, kwargs...)

K-fold cross-validation of the lasso path of LassoPath (with the same options and keywords): the path on all the data gives the levels, each fold's path is computed on the other folds at those levels, and the mean squared error on the held-out fold estimates the prediction error at each level. Standardization and the intercept are computed on each training fold, so nothing leaks from the held-out one.

cvm is the average of the fold errors weighted by the fold sizes, and cvse its standard error, sqrt(∑ₖ nₖ (eₖ - cvm)² / n / (K - 1)), as in glmnet. λmin minimizes cvm, and λ1se is the largest level whose cvm is within cvse of the minimum (the one-standard-error rule). A fold path that stops early (max_hat_s) leaves the remaining levels out of the averages.

The folds are a balanced random assignment drawn from rng, or the vector folds of fold labels 1, …, K given, for example grouped or blocked folds for dependent data. With threads, the folds run as tasks on the available threads; each fold draws its random coordinate orders from a generator seeded from rng, so that the result does not depend on the number of threads.

Observation weights and an offset (see lasso) follow the observations into the folds. The fold errors are then the weighted mean squared errors of y - offset, and the folds are weighted by their sums of weights. With gram = :auto, the choice for the full data is used for every training fold, so that holding out observations does not switch a nearly square design from the Gram form to the residual form. gram = true or false selects the form explicitly for all fits.

Returns a CVLassoPath; coef(cv) and predict(cv, X) use the solution at λ1se, or at λmin with λ = :λmin.

bic(path::LassoPath, X, y)

Information criteria along the lasso path fitted to X and y, one per level of path.λpath:

  • aic = n log(RSS/n) + 2 df;
  • bic = n log(RSS/n) + log(n) df;
  • ebic = bic + 2γ log C(p, s), the extended BIC of Chen and Chen (2008) for large model spaces, with s nonzero coefficients among p.

RSS is the residual sum of squares and df the number of nonzero coefficients plus one for an intercept, an unbiased estimate of the degrees of freedom of the lasso (Zou, Hastie and Tibshirani, 2007). A level with df ≥ n gets NaN. The level that minimizes a criterion c is path.λpath[argmin(c)], with the NaNs left out.

HighDimensionalModels.fused_lasso — Method
fused_lasso(X, y, λ1, λ2; intercept = false, max_iter = 20_000,
            abstol = 1e-8, reltol = 1e-7, df_tol = 1e-4)
fused_lasso(y, λ1, λ2; kwargs...)

Minimize norm(y - intercept - X*beta)^2/(2n) + λ1*norm(beta,1) + λ2*sum(abs, diff(beta)). Regression uses accelerated proximal gradient with backtracking and ProximalBase's exact sparse fused-lasso proximal operator. The signal form is a single proximal step. Columns retain their original scales and order. The stopping test is the proximal-gradient residual in coefficient units, norm(beta - prox(beta - step*gradient))/step, against sqrt(p)*abstol + reltol*max(norm(X'y/n), 1). Before reporting convergence, the residual is checked at the returned coefficients using the original design; dual_residual reports that value. The defaults above apply to Float64 data; other floating types retain abstol = 1e-7, reltol = 1e-6. This is an optimality-residual test, not a uniform relative coefficient-error guarantee.

HighDimensionalModels.generalized_lasso — Method
generalized_lasso(X, y, D, λ; intercept = false, rho = nothing,
                  max_iter = 20_000, abstol = 1e-9, reltol = 1e-8,
                  df_tol = 1e-4)
generalized_lasso(y, D, λ; kwargs...)

Minimize norm(y - intercept - X*beta)^2/(2n) + λ*norm(D*beta, 1) by ADMM. D can be dense or sparse, for example graph_difference. The signal form uses the identity design without allocating it. ADMM factors X'X + rho*D'D once; [X; D] must have full column rank. rho is on the unnormalized-loss scale and defaults to the larger of n*λ and the average column squared norm of the centered design (one for a signal fit).

No standardization is applied, since it would change the difference penalty. At zero penalty the minimum-norm least-squares solution is returned. The result reports nonconvergence if the residual stopping criteria are unmet. dof is rank(X * null(D[inactive, :])), including an intercept when fitted; inactive rows satisfy abs(D*beta) <= df_tol. At transition points the degrees-of-freedom estimate is sensitive to this numerical tolerance. Compared with R's genlasso, use lambda_R = n*λ. The default residual tolerances above apply to Float64 data; other floating types retain abstol = 1e-7, reltol = 1e-6. Residual convergence does not certify a uniform relative coefficient error on ill-conditioned designs.

HighDimensionalModels.trend_filter — Method
trend_filter(y, λ; order = 1, x = nothing, kwargs...)
trend_filter(X, y, λ; order = 1, x = nothing, kwargs...)

Trend filtering with λ * norm(difference_matrix(p, order+1; x)*beta, 1) and loss norm(y-X*beta)^2/(2n). order = k gives piecewise polynomials of degree k (order zero is total-variation denoising). x gives the ordered coefficient locations, not the rows of the design.

For order > 0, the specialized ADMM of Ramdas and Tibshirani (2016) splits the order-k divided differences and applies exact TV denoising in each iteration. Sparse banded normal equations avoid a dense identity in signal fits. Keywords and termination diagnostics follow generalized_lasso. For a signal, default rho = n*λ*spacing^order follows the paper's spacing rule. With a design, it is at least the average column squared norm times spacing^(2order). R's glmgen::trendfilter uses lambda = n*λ.

Float64 linear signal fits (order = 1, positive reltol) stop using a feasible primal-dual gap at most 0.3reltol times the primal objective, with primal and dual residuals at most five times their usual bounds. The gap is checked every ten iterations and at the first and final iteration. Near a zero objective the original residual test is used. Other fits and absolute-only tolerances retain residual stopping. Other Float64 trend fits default to abstol = 1e-8, reltol = 1e-7. Linear signals and other floating types retain 1e-7, 1e-6. Explicit tolerances override these defaults, including on paths and CV folds.

HighDimensionalModels.double_selection — Method
double_selection(y, d, X; method = :doubleselection, level = 0.95, forced = Int[], post = true, kwargs...)

Inference on the effect α of a treatment d in y = αd + Xβ + ε with many controls X, after selecting them by rlasso (kwargs go to it), as R's hdm rlassoEffect computes it:

  • method = :doubleselection (Belloni, Chernozhukov and Hansen, 2014): select the controls that predict y and those that predict d, then regress y on d, the union of both (and the forced controls) and an intercept. The standard error is the robust one of hdm, √(mean(v² ξ²) / (n mean(v²)²)), with ξ the residuals of that regression scaled by √(n/(n - s - 1)) for s selected controls, and v the residuals of d on the selected controls and an intercept.
  • method = :partialling: regress the residuals of rlasso of y on X on those of d on X, with an intercept; the standard error is that of least squares, as in hdm.

The confidence interval is estimate ± z se with the normal quantile z at level. Returns a TreatmentEffect.

HighDimensionalModels.rlasso — Method
rlasso(X, y, options = CDOptions(); post = true, intercept = true, c = post ? 1.1 : 0.5,
       γ = 0.1 / log(n), max_iter = 15, tol = 1e-5)

The lasso with data-driven penalty loadings as R's hdm computes it (rlasso with its defaults: heteroskedastic and X-independent penalty), the procedure of Belloni, Chen, Chernozhukov and Hansen (2012):

  1. Start from the residuals of least squares on the five columns most correlated with y, and compute the loadings Γⱼ from them (see feasible_lasso!).
  2. Solve the lasso ‖y - β₀ - Xβ‖² / (2n) + λ0 ∑ⱼ Γⱼ |βⱼ| with λ0 = theory_lambda(n, p; c, γ), at half the level in the first step when post is true, as hdm does.
  3. With post, refit least squares on the selected columns; update the loadings from the residuals; repeat 2–3 until the standard deviation of the residuals changes by less than tol, or max_iter times.

The coefficients returned are the refitted ones when post is true. With intercept, the columns and y are centered and β₀ = ȳ - x̄'β. Each lasso is solved by coordinate descent with options, warm started from the previous one. Returns an RLassoSolution. See also post_lasso and double_selection.

theory_lambda(n, p; c = 1.1, γ = 0.1 / log(n))

minimize  ‖y - β₀ - Xβ‖² / (2n) + λ0 ∑ⱼ Γⱼ |βⱼ|,   Γⱼ = sqrt(∑ᵢ (Xᵢⱼ - x̄ⱼ)² εᵢ² / n),
