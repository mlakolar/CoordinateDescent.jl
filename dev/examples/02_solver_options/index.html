Options of coordinate descent: CDOptions, keywords, and what a run reports

Every solver takes a CDOptions: the high-level ones (lasso, sqrtlasso, LassoPath) as their last positional argument, coordinatedescent! as its fourth. They also take its fields as keywords, as in lasso(X, y, λ; opttol = 1e-8), and a random number generator rng for the random order. They run the coordinate descent of ProximalSolvers (CDSolver) with these options. solve!(x, f, g, options) does what coordinatedescent! does and returns how the run went (a CDResults).

using HighDimensionalModels, ProximalBase
using LinearAlgebra, Printf, Random

Random.seed!(2)
Random.TaskLocalRNG()

n observations of p columns with correlation ρ between every pair (a common factor), and ten nonzero coefficients

function simulate(n, p, ρ)
  X = sqrt(ρ) * randn(n) .+ sqrt(1 - ρ) * randn(n, p)
  β = zeros(p)
  β[1:10:100] .= 1
  X, X * β + randn(n)
end

objective(X, y, λ, x) = sum(abs2, y - X * x) / (2 * size(X, 1)) + λ * norm(x, 1)
objective (generic function with 1 method)

solves the lasso with solve!, from zero; returns the solution, the results (passes, converged, …) and the shortest time in seconds of three runs

function timed_solve(X, y, λ, options)
  x, r, t = SparseIterate(size(X, 2)), nothing, Inf
  for _ in 1:3
    x = SparseIterate(size(X, 2))
    t = min(t, @elapsed r = solve!(x, CDLeastSquaresLoss(y, X), NormL1(λ), options))
  end
  x, r, t
end

opt_tol: when to stop

Coordinate descent stops after a full pass and a pass over the active set in which no coefficient changes by more than the tolerance. The default 1e-7 gives about seven correct digits of the coefficients.

xstar, = timed_solve(X, y, λ, CDOptions(; opt_tol = 1e-14))
Fstar = objective(X, y, λ, xstar)
println("  opt_tol  passes  |F - F*| / F*  max |β̂ - β*|")
for opt_tol in (1e-2, 1e-4, 1e-7, 1e-10)
  x, r = timed_solve(X, y, λ, CDOptions(; opt_tol))
  @printf("%8.0e  %6d  %13.1e  %12.1e\n", opt_tol, r.passes,
          abs(objective(X, y, λ, x) - Fstar) / Fstar, norm(x - xstar, Inf))
end

relative_tol: a tolerance that does not depend on the units

With relativetol = true (the default) the change of βₖ is measured as |Δβₖ| ‖X[:, k]‖ / √n, the size of the change in the fitted values, and compared with opttol ‖y‖ / √n. Expressing y in a unit a thousand times smaller scales β̂ and λ by 1000 but changes neither the passes nor the accuracy. With relativetol = false, |Δβₖ| is compared with opttol itself, so the same opt_tol gives about seven correct digits in one unit and ten in the other. (The random number generator is reset before each run, so that the coordinates are visited in the same order.)

println("  relative_tol  unit of y  passes  max |β̂ - β*| / max |β*|")
for relative_tol in (true, false), scale in (1, 1000)
  Random.seed!(10)
  x, r = timed_solve(X, scale * y, scale * λ, CDOptions(; relative_tol))
  @printf("  %-11s  %9s  %6d  %10.1e\n", relative_tol, scale == 1 ? "1" : "1/1000",
          r.passes, norm(x / scale - xstar, Inf) / norm(xstar, Inf))
end

order and anderson: the order of the coordinates

order = :random (the default) visits the coordinates in a new random order in every pass, drawn from the random number generator rng, a keyword of every solver (by default the global generator, which Random.seed! resets), and by default with momentum (see below). order = :cyclic visits them in the order 1, 2, …, p, which is faster on independent columns but much slower when the columns share a common factor. The older option randomize = true or false means order = :random or :cyclic.

With order = :cyclic, anderson = K extrapolates from the last K + 1 passes over an unchanged active set (Anderson acceleration), and keeps the result when it lowers the objective. It saves passes where coordinate descent needs many, as at small penalties with correlated columns, but it keeps the weakness of the cyclic order under a common factor. With order = :random, each pass over the active set starts from an extrapolated point (Nesterov momentum), by default for the built-in losses; it works with the random order, so it also helps under a common factor. momentum = false turns it off.

Xiid, yiid = simulate(500, 200, 0.0)

warmstart and numsteps: where to start

warmstart = true (the default) starts from the x passed in. With warmstart = false, x is set to zero and the problem is solved along num_steps penalty levels, from λmax, the smallest λ with a zero solution, down to λ, each started from the previous solution and screened with the sequential strong rule. Every level is solved to the tolerance, so for one λ the path costs more passes than a direct start, unless a direct start converges slowly, as with many more columns than rows and a small λ; a short path then pays off.

Xwide, ywide = simulate(100, 5000, 0.0)
println("  design        λ / λmax  warm_start  num_steps  passes  time (ms)")
for (name, Xd, yd) in (("n=500, p=200", X, y), ("n=100, p=5000", Xwide, ywide))
  λmax = maximum(abs, Xd' * yd) / size(Xd, 1)
  for (warm_start, num_steps) in ((true, 50), (false, 10), (false, 50))
    _, r, t = timed_solve(Xd, yd, 0.02λmax, CDOptions(; warm_start, num_steps))
    @printf("  %-13s  %8.2f  %-9s  %8s  %6d  %9.2f\n", name, 0.02, warm_start,
            warm_start ? "-" : string(num_steps), r.passes, 1000t)
  end
end

max_iter, and what a run reports

maxiter caps the number of passes. Running out of passes gives a warning and r.converged = false, and r.maxchange > r.tolerance tells how far the last pass was from the stopping rule (both scaled as with relativetol). The options can also be given as keywords, which change those passed.

flush(stdout)
x = SparseIterate(size(X, 2))
r = solve!(x, CDLeastSquaresLoss(y, X), NormL1(λ), CDOptions(); max_iter = 5)
println("  converged = $(r.converged) after $(r.passes) passes; ",
        @sprintf("maxchange = %.2e, tolerance = %.2e", r.maxchange, r.tolerance))

rng: reproducible random orders

A generator of its own makes the random order, and so the passes, the same from run to run without reseeding the global generator, and gives parallel fits independent streams.

passes(rng) = lasso(X, y, λ; rng).iterations
println("  passes with Xoshiro(1), twice: ", passes(Xoshiro(1)), ", ", passes(Xoshiro(1)))
  passes with Xoshiro(1), twice: 67, 67

Float32

The iterate, the data and the penalty share one floating point type. A Float32 solution is accurate to about 1e-7 relative to its size, so a tolerance at that level may never be met: use opt_tol ≥ 1e-6.

x32 = SparseIterate(Float32, size(X, 2))
r = solve!(x32, CDLeastSquaresLoss(Float32.(y), Float32.(X)), NormL1(Float32(λ)), CDOptions(; opt_tol = 1e-6))
@printf("  %s solution in %d passes, max |β̂ - β*| = %.1e\n", eltype(x32), r.passes,
        norm(Vector(x32) - xstar, Inf))
  Float32 solution in 65 passes, max |β̂ - β*| = 2.2e-06
