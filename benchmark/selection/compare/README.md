# Direct selection comparisons on Discovery

This campaign compares the issue-82 implementation at `ab544aec2a4f24b41ec5befd4467024ce2e29f16` with SLOPE.jl 1.3.1, Knockoffs.jl 3.1.4, GLMNet.jl, and R SLOPE/knockoff/glmnet/stabs. Exact installed versions and manifests are retained with the results. All numerical execution, timing, profiling, simulation, and aggregation run inside Slurm allocations on Discovery.

## Timing protocol

Seven independent Julia/R process replications use identical inputs. Benchmark workers are serialized on one AMD EPYC-7513 node. BLAS/OpenMP threads are one, Julia threads two; ordinary fits use one thread and an explicitly labelled CPSS variant uses two. Every case is warmed, then measured in three batches. Batches adapt to at least roughly 20 ms, up to 20 calls, to reduce R clock granularity effects. Report medians across processes of within-process medians, plus paired runtime ratios and replication ranges. Julia profiles are collected separately in every process. Timing excludes package startup/JIT, input generation, input parsing, output serialization, and independent accuracy checks. Allocation counts cover the Julia heap and omit foreign C++/Fortran allocations; they cannot compare total memory across these backends. Peak resident memory and cold-start costs are not assessed.

SLOPE solves exactly the same 20-level penalty path, without intercept or standardization, using explicit BH weights and scalar factors; R uses gamma=1. The R automatic hybrid solver is the primary R comparison. Optional FISTA diagnostics are retained from the pilot. Full proximal fixed-point residuals, objective differences and coefficient differences are checked using one common calculation. The initial pilot found that R FISTA at tol=1e-8 did not reach the common certificate. An attempted tol=1e-14 calibration was stopped after spending minutes on the first small path. Production uses R auto, which already meets the same certificate as CD and SLOPE.jl; no FISTA speed ranking is claimed. Cases: dense n=600,p=200,rho=.3; wide n=200,p=1000,rho=.3; correlated n=p=400,rho=.8; sparse n=600,p=1000,density=.02. Columns are scaled before timing and identical across packages.

Gaussian constructors include selecting the equicorrelated diagonal, covariance factorization and sampling. Knockoffs.jl MVR/maxent variants are separate algorithm choices. Fixed-X constructors receive columns of Euclidean norm one. Joint-lasso statistics use the exact same augmented design and lambda=.04, with no intercept or standardization. CPSS timings share 30 complementary pairs, lambda=.08, cap=10, cutoff=.8; R uses a matched custom fixed-penalty capped selector. These component comparisons do not time each package's different default cross-validation workflow.

## Shared-design simulations

Seven independently generated seed shards each contain 20 datasets per scenario (140 per scenario; 840 total). All implementations receive identical X and y. Scenarios: iid Gaussian; Gaussian AR(1),rho=.4; AR(1),rho=.8; weak-signal AR(.4); global-null AR(.4); wide AR(.4),n=180,p=300. Other cases use n=300,p=100. Non-null cases have 20 alternating-sign signals, coefficient magnitude 4.5/sqrt(n), or 3/sqrt(n) in the weak case; noise standard deviation is one. Population covariance is known.

SLOPE uses the same BH sequence targeting .1. In these random/correlated designs its FDR is assessed empirically; the orthogonal-design theorem does not establish control here.

Matched knockoff-statistic comparisons share the exact knockoff matrix, constructed with a common Gaussian noise matrix. Equicorrelated, MVR and maximum-entropy diagonal choices are distinguished. MVR/maxent diagonals come from Knockoffs.jl, while the shared conditional sampler is the issue-82 sampler. Both Julia lasso engines and R glmnet fit at prespecified lambda=.04; all use knockoff+ at .1. Fixed-X is included only when n>=2p. Native Knockoffs.jl equicorrelated/MVR and R equicorrelated constructor pipelines are additionally reported using the same data but independent language-specific noise draws; these are not exact shared-knockoff comparisons. A repeated conditional-covariance diagnostic gates the interpretation of each native constructor.

CPSS shares complementary pairs and compares caps 10 and 20 at lambda=.06, cutoff=.8. Its basic bound is q^2/[p*(2*.8-1)], conditional on the documented null-selection-probability condition. It is not an FDR target of .1. R also evaluates its usual lasso-path selector at q=10; that is a separate statistical procedure.

## Targeted calibration follow-up

The primary study found substantial FDR inflation for explicit BH weights in nonorthogonal designs. A targeted follow-up reuses the same 840 saved datasets and seven seed shards, evaluating the existing SLOPE.jl `regweights(...; type=:gaussian,n)` sequence divided by sqrt(n). CD, SLOPE.jl and R all receive that exact sequence. R's native `lambda="gaussian", alpha=1/sqrt(n)` option is also evaluated, with the actual weight difference retained. Other settings and input matrices are unchanged. This is a paired exploratory comparison prompted by the primary result; it is not an independent confirmation campaign or a proof of correlated-design FDR control. No additional timing claims are made. Run `gaussian.sbatch` after `campaign.sbatch`; its first shard is a bounded interface canary and the remaining six use two srun workers. Outputs have a separate `gaussian-` prefix and do not change the primary results.
