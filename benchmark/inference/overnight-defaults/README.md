## Fully solved score development extension

The 20-dataset pilot is preserved under results/discovery-20261026-development20. Same-seed development is expanded to100 per design. No confirmation data have been used. Naive selected-model refitting did not broadly improve coverage. The promising Gaussian robust-HC1 regularized initializer therefore remains in the comparison rather than being replaced by refitting on preference alone.

`score-study.jl` freezes the estimated nuisance slopes and projection score, then jointly solves the empirical intercept and target score equations. The logistic target derivative and variance are evaluated at that root. Model-based logistic variance and an HC1 residual sandwich are distinct comparisons. Gaussian roots agree with the direct two-moment solution. All roots require small moment residuals, finite positive SE and positive target derivative; analytic derivatives are checked by independent finite differences. These checks certify numerical calculations, not statistical coverage. Compare CVmin, a half-relaxed CVmin/refit initializer, and a one-standard-error-selected/refitted initializer. This is development of distinct estimators, not a claim that the original one-step estimator has silently changed.

`qp-score.jl` applies the same full moment solution to a certified Gaussian QP projection at the universal constraint. It retains the conventional one-step result alongside the new score estimator, for CVmin and refitted initializers. Unit-derivative normalization is not being silently applied to the standard Javanmard–Montanari estimator. Neither the universal constraint nor the score variant is presumed calibrated. Half-universal feasibility failures remain adverse evidence.

`hdm-logistic-variance.R` instruments a copy of the native function only to return internal fit and selection metadata. On the first replication, native coefficients and native SE must reproduce the uninstrumented public function within1e-10. Native selection/refitting coefficients remain fixed. The source computes S22 using l3$index although l3 is a standard glm object. Separate audit rows compare the full selected-model Hessian variance, its HC1 sandwich, and max(native S21,full-model S22). These are explicitly modified variance candidates, not relabeled native defaults. Errors and source convergence/separation warnings remain failures.

The score and variance-audit analyzers require every requested target and convergence before a dataset contributes to a method summary. They preserve partial target records and report incomplete datasets separately. Per-target results are retained. Diagnostic timings include compilation, selection and shared calculations; they are not matched engine benchmarks. All numerical processing remains on Discovery compute nodes.

`qp-adaptive.jl` next tests a native-sslasso-inspired per-row convergence search, retaining strict feasibility and primal-dual checks. This is a reproducible computational selection rule; solver failure does not prove mathematical infeasibility. Unlike original sslasso, this uses the package's certified solver and CV initialization, so it is explicitly a distinct recipe.
